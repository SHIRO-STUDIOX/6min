# MVP Scope — SHISH

**Status:** `APPROVED` product boundaries + `PROVISIONAL` engineering subdivisions. **Owner:** product owner. **Contract:** what to build now, what not to promise.

## هدف واقعی MVP
ساخت **پلتفرم قابل استفاده یادگیری زبان آلمانی** با چرخه «ویدیوی ~۶ دقیقه‌ای → تمرین‌های مرتبط → ثبت تلاش/اشتباه → بازشدن درس بعد → تکرار» برای دوره ۶۰ قسمتی. تمرکز: سناریوهای پایه و قابلیت اتکا؛ طراحی بصری اختصاصی کارت‌ها توسط مالک در development/QC تکمیل می‌شود.

## دامنه‌های داخل MVP
| Domain | Required behavior | Acceptance signal |
|---|---|---|
| Curriculum | قرارداد ۶۰ درس شماره‌دار؛ فعلاً حداقل سه lesson fixture آلمانی با ID پایدار و ویدیوی تست مجاز | API درس و sequence بدون hardcode در UI |
| Classroom | Header سه جزیره، Action Center افقی، Dock سه‌مقصدی؛ ورود به درس و stage | مرحله فعال/قفل در UI و دسترسی منطقی جدا |
| Video | پلیر آماده واقعی، پوستر ویدیو، پیگیری بخش‌های پخش‌شده؛ مشاهده حداقل ۸۰٪ بازه‌های منحصربه‌فرد | seek انتها به‌تنهایی credit نمی‌دهد |
| Exercises | adapter برای ۴ FSM فعلی؛ امتیاز نسبی تلاش کامل، retry، اشتباه | attempt با source و contentVersion در سرور |
| Progress | وزن قابل تنظیم per lesson + defaults؛ best full attempt و اصلاح مرور؛ unlock پایدار | هیچ lock مجدد با تلاش ضعیف‌تر |
| Mistakes | تاریخچه تغییرناپذیر؛ فهرست زمانی جدید→قدیم؛ مرور فقط سؤال غلط؛ برگشت به تمرین؛ نتیجه و انتخاب بازگشت/ادامه | اصلاح معتبر score را افزایش می‌دهد، دوبار حساب نمی‌شود |
| My Path | ۶۰ درس در فهرست عمودی؛ نمایش ۶۰→۱؛ جدیدترین درس بازشده «درس فعلی» | تمرکز/اسکرول درست، نقطه‌های ناوبر |
| Profile | نام و عکس قابل تغییر، خلاصه مسیر و ناوبری | اطلاعات پس از ورود مجدد پابرجا |
| Auth | شماره موبایل + ورود با OTP یا رمز؛ بازیابی رمز با OTP | نشست امن، محدودیت تلاش، شماره تأییدشده |
| Guest | سه درس ابتدایی رایگان بدون حساب؛ داده موقت؛ انتقال خودکار به حساب جدید و ادغام با رضایت حساب موجود | شکست ورود/ادغام داده را پاک نمی‌کند |
| Commerce | خرید یک‌باره کل دوره با پرداخت خارجی؛ verify سروری | bypass دسترسی پولی از کلاینت ناممکن با تغییر UI |
| Persistence | PostgreSQL؛ draftهای لازم، watch ranges، تلاش‌ها، mistakes، entitlements | reload/session recovery |
| Quality | typecheck، build، lint درست، تست‌های دامنه و مسیرهای مهم | CI سبز در subset مصوب |

## رفتار پایه کاربر
1. مهمان وارد تجربه می‌شود؛ معرفی کوتاه و «شروع درس اول» برای کاربر جدید (`APPROVED`).
2. کاربر ویدیو را می‌بیند، تمرین می‌کند، جواب‌های غلط ثبت می‌شوند؛ امکان retry وجود دارد.
3. درس بعد وقتی `effectiveLessonScore >= threshold` فعال می‌شود. وضعیت «آماده ادامه» مستقل از نقص تمرین‌هاست.
4. درس ۱–۳ رایگان‌اند. مهمان پس از تکمیل بخش رایگان پیشنهاد ثبت‌نام و خرید می‌بیند؛ مرور درس‌های رایگان ادامه‌پذیر است.
5. خریدار پس از verify پرداخت حق دسترسی کل دوره را می‌گیرد، اما **نه حق ردکردن قفل آموزشی**.
6. بازگشتی به آخرین فعالیت واقعی کلاس می‌رود؛ Profile/My Path از داده مشترک استفاده می‌کنند.

## در محدوده ولی بدون طراحی اختصاصی نهایی
- Shell کارت‌های تمرین ویدیو/واژگان/گرامر/دیکته/تلفظ؛ UI حداقلی، قابل لمس و قابل استفاده.
- راهنماهای کوتاه داخل صفحه، خطاهای فرم‌ها، loading/empty/error.
- Focus Mode و gestureهای پایه متناسب با تصمیم‌های قبلی؛ جزئیات player-level fullscreen و learning moments بمانند `DEFERRED_QC` مگر برای قابلیت اصلی لازم باشند.
- StageIndicator باید هر مرحله حتی قفل را برای مشاهده shell انتخاب کند؛ عملکرد آموزشی stage قفل محدود می‌ماند.

## غیرهدف‌های نسخه اول (`NON_GOAL`)
- موتور AI شخصی‌سازی خودکار، برنامه‌ریز مرور فاصله‌دار، تکرار هوشمند محتوای جدید.
- ادعای سنجش «تسلط به آلمانی» بر مبنای صرفاً امتیاز وزنی.
- بک‌اند مستقل NestJS یا Python؛ موتور AI بیرونی در صورت نیاز پشت server-side API adapter.
- توسعه یک video player جدید از صفر؛ بازسازی controls آماده.
- XP/Streak economy پیچیده و الگوریتم جریمه تغییر tab/محدودکردن seek در نمونه قدیمی؛ مگر بعداً تأیید شود.
- نمودارهای پیچیده، رتبه‌بندی، badges اجتماعی، gamification اجباری، سیستم CMS تمام‌عیار برای MVP.
- نهایی‌کردن aesthetic هر کارت، glow، gradient، sticker و motion قبل از functional MVP.
- اپ native یا PWA نصب‌شونده به‌عنوان تعهد همین برش؛ API برای آینده آماده باشد.

## تعریف Done سطح MVP
- با داده fixture نسخه‌دار: کاربر ناشناس درس ۱ را شروع، ویدیو واقعی مشاهده، تلاش کامل و مرور غلط، unlock درس ۲، refresh و resume را تجربه کند.
- مهمان از درس‌های پولی دور بماند؛ ورود/ادغام/خرید و بازگشت از خطا تست شود.
- کاربر دارای حساب بتواند ۶۰ آیتم مسیر، پروفایل و اشتباهات را با state واقعی مرور کند؛ محتوا فقط برای دروس آماده منتشر شود.
- هیچ کلید سرویس خارجی در bundle کلاینت نباشد.
- محدودیت‌های unresolved خارج از build با `assumptions-and-blockers.md` شفاف باشند.

## نسبت ۶۰ درس و محتوای نمونه
۶۰ **جایگاه/metadata قابل تعریف** با داشتن تنها چند درس fixture به معنی ۶۰ درس قابل انتشار نیست. `availableContent`، `pedagogicalUnlocked` و `commerciallyEntitled` سه شرط مستقل‌اند. درس بدون محتوای publish شده نباید ظاهراً قابل شروع شود؛ وضعیت و متن دقیق آن در فاز QC تصمیم می‌شود.
