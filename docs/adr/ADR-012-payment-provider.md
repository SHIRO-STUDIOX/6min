# ADR-012 — TEST_ONLY payment verification adapter

Provider, price, currency and public hosting remain UNRESOLVED. Implement PaymentGateway behind explicit mock+development/test guard and a dedicated >=32-character server secret. Fictional1000 TEST units are a fixture, not approved real pricing/currency. No money/card/SMS/network gateway operation. Simulator hosted locally represents external redirect and signed callback states; real external sandbox vendor proof is unrun and is a production integration gate.

Stored purchase owner, amount/currency/product/ref/intent are authoritative. HMAC signed strict event normalized canonical shape, verified server-side before lock/transaction, matches owner/reference/order/amount/currency. Atomic verified purchase + immutable transaction/event history + unique active course entitlement. Return query has no write; duplicate callbacks safe. Concurrent initiation same key+body same order; changed body409. Callback after browser close and delayed success converge; late success can supersede timeout/failure if verified; later conflicting failure cannot revoke success and is retained for reconciliation. Display expiry at30min does not discard a legitimate late verified provider callback. No automated refund/revoke policy invented.

Internal product ID shish-de-60 maps Blueprint full60 course; existing schema status verified represents verifiedSuccess. Buying affects commerce only; publication/pedagogy remain server gates. All purchase reads/mocks owner-only, Origin on browser writes, callback signature independent of browser session. Mock redirect exact same-origin simulator path allowlisted. Real vendor adapter must separately whitelist TLS vendor hosts and verify network callback/source/retries. One verified entitlement across retry purchases; records kept for audit. No deploy/merge authorized.
