# ADR-009 — Exact scoring and review amendments

Context: owner selected best full attempt + later correct reviews, not cross-attempt answer mixing. New baselines may exclude old corrections; previously earned progress/unlocks must not be removed. Defaults remain unresolved; fixture policy is DEMO_ONLY.

Decision: exact nonnegative rational arithmetic using BigInt numerator/denominator for policy comparison and saved earned fractions. No rounded floating value determines unlock. Decimal numeric columns are display/projection only. Select best full by canonical fraction (fixed published question count), earliest completion then ID for ties; last full independently selected. Later correction eligibility compares timestamps entirely in PostgreSQL (no JS millisecond truncation). On changed baseline, expose current calculation separately; preserve max earned exercise/lesson fractions. This is the blueprint's PROVISIONAL compatibility rule, not a new product formula. Persist successor unlock monotonically; commercial entitlement is still independent. At least one full attempt plus confirmed video is required before threshold can unlock, but remaining unfinished exercises need not all be perfect.

Immutable attempt receipts preserve original idempotent outcomes even after later progress changes. Append-only mistake events and scoped current projection distinguish incorrect/corrected/reopened; repeated correction adds no points. Review only currently wrong exact question versions with an existing full baseline; old full results are never rewritten. Published-version changes with existing progress fail closed for explicit future migration rather than silently regrade history.

Rollback: revert code, retain audit/events/receipts and rational fields. No destructive reversal or learner data deletion. Approval: reversible technical compatibility choice explicitly allowed by the progression blueprint and current owner execution instruction. Production policy/defaults and content migration remain owner gates.
