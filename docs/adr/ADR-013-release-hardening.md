# ADR-013 — Final functional hardening and dependency security

Expected-subject header is optional consistency detection only: actual opaque cookie/session authenticates, header cannot select or authorize another user. Live mutation closures bind original learner scope; old form after cookie account switch returns409. Watch IDs and all domain rows still require actual ownership. No anonymous header proof. Nonsecret storage event marker reloads other tabs after auth/logout; raw drafts remain scoped in IndexedDB. Direct account forms, avatar bytes, attempts, review, drafts, context, support and checkout use the guard. Actual last-activity stage preserved on root/Dock resume and expired-session intent. Return paths remain bounded internal routes.

Append-only payment transactions/events enforced in additive0013; no automatic refunds, entitlement revocation or deletion. Mock entitlements excluded from production commerce reads. API errors log requestId/code/status only, never input, query, phone, OTP, password, token, payment payload or raw DB exception. Security headers limit framing to same origin (Sandbox iframes preserved), sniffing/referrer and unused camera/location; microphone prototype remains intact. Production CSP/HSTS/TLS require actual hosting and media origins, so no untested blanket policy is claimed.

Frozen npm lockfile and CI npm ci. Initial registry audit found5 vulnerable production dependency groups, including critical Next advisories. Update to pinned Next16.4.6, Drizzle0.45.4, Sharp0.35.5, Zod4.6.7 and PostCSS8.5.33, matching Next ESLint packages. These are dependency security updates within MVP scope. Zod4 record declaration explicitly supplies string keys; all strict body/public DTO/grading checks retested. Sharp raster behavior tested after native update. Prior ADR version selections are historical, superseded here. Production audit repeated after install; remote vendor/hosting security still unrun. No broad npm audit --force or disabled signature/TLS checks.

Connected templates registered in Sandbox and exercised375/768/1200; earlier S9/S10 routes preceded these integration stories, now corrected for continuing QC. Old components/FSMs/tokens retained. Theme-dependent Sandbox initial hydration now waits until mount before using resolved theme, preserving SSR/client agreement without hiding errors. New UI remains functional engineering, not final visual approval.
